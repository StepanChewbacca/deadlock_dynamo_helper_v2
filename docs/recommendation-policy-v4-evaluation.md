# Recommendation Policy V4 Evaluation

Recommendation Policy V4 Evaluation is a diagnostic offline policy evaluation pipeline. It joins held-out Behavioral V4 and Value V4 validation rows and estimates how a stochastic value-tilted policy would behave under recorded candidate sets.

It does not authorize production rollout.

## Inputs

Default directories:

```text
/app/apps/api/storage/recommendation-decision-dataset-v4
/app/apps/api/storage/recommendation-behavioral-v4-training
/app/apps/api/storage/recommendation-value-v4-training
```

Environment overrides:

```text
DEADLOCK_RECOMMENDATION_POLICY_V4_DATASET_DIR
DEADLOCK_RECOMMENDATION_POLICY_V4_BEHAVIORAL_DIR
DEADLOCK_RECOMMENDATION_POLICY_V4_VALUE_DIR
```

The evaluator verifies:

- Dataset V4 audit and dataset SHA-256
- Behavioral V4 audit, validation artifact SHA-256, and model SHA-256
- Value V4 audit, validation artifact SHA-256, and model SHA-256
- both training manifests reference the same immutable Dataset V4 artifact
- model versions match the supported evaluator contract
- Value V4 explicitly forbids causal interpretation

Evaluation rows are the decision-ID intersection of Behavioral V4 and Value V4 held-out validation artifacts. The evaluator does not use either model's training rows.

## Policies

The estimated behavior policy is:

```text
softmax(BehavioralV4Score / behaviorTemperature)
```

These propensities are estimated from historical observed player actions. They are not actual probabilities logged by the historical production system.

The target policy is:

```text
softmax(
  (BehavioralV4Score + targetValueWeight * logit(ValueV4Probability))
  / targetTemperature
)
```

Both policies are restricted to the candidate actions recorded at decision time. The current item catalog is never used to reconstruct a newer candidate set.

## Estimators

For supported held-out decisions, the evaluator reports:

- observed outcome mean
- clipped inverse propensity score estimate
- self-normalized inverse propensity score estimate
- direct-method estimate from Value V4
- doubly robust estimate
- effective sample size and effective sample-size ratio

The importance weight is:

```text
pi_target(observedAction | context)
-----------------------------------
pi_behavior_estimated(observedAction | context)
```

Weights above `maxImportanceWeight` are clipped. Decisions below `minBehaviorProbability` are preserved in the decision artifact with an exclusion reason and are not included in the estimators.

## Diagnostics

The audit and evaluation include:

- candidate coverage
- estimated behavior-policy support rate
- missing and mismatched held-out joins
- raw and clipped weight distributions
- clipping rate
- behavior-probability distribution
- target-policy entropy
- effective sample size
- IPS versus SNIPS stability

`decision-evaluation.ndjson` contains candidate-level behavior probabilities, target probabilities, value probabilities, and per-decision estimator contributions.

`match-summary.ndjson` contains replayable match-level aggregates.

## Match-level bootstrap

Confidence intervals are generated by sampling held-out matches with replacement. Every selected match contributes all of its supported decisions. This preserves within-match outcome and decision dependence better than independent decision-level resampling.

The bootstrap is deterministic for a fixed `bootstrapSeed` and reports 95% intervals for estimator values and deltas versus the observed outcome mean.

## Shadow-readiness gate

The diagnostic gate checks:

- at least 200 supported decisions
- at least 30 held-out matches
- at least 95% recorded candidate coverage
- at least 90% estimated behavior support
- effective sample-size ratio of at least 20%
- no more than 10% clipped weights
- IPS and SNIPS absolute difference no greater than 0.05
- non-negative lower 95% bootstrap bound for the doubly robust delta
- Behavioral V4 and Value V4 training release gates passed

Even when every numeric condition passes, `productionRolloutAuthorized` remains `false`. Actual historical propensities were not logged, Value V4 is observational, and unobserved confounding can invalidate causal or policy-value claims.

## Persistence

Default output directory:

```text
/app/apps/api/storage/recommendation-policy-v4-evaluation
```

Override:

```text
DEADLOCK_RECOMMENDATION_POLICY_V4_OUTPUT_DIR
```

Artifacts:

- `decision-evaluation.ndjson`
- `match-summary.ndjson`
- `evaluation.json`
- `audit.json`
- `manifest.json`

NDJSON artifacts are written to partial files and promoted only after their pass succeeds. JSON artifacts are replaced atomically.

## API

Start evaluation:

```text
POST /deadlock/analysis/recommendation-policy-v4-evaluation/start
```

Optional fields:

- `behaviorTemperature`
- `targetTemperature`
- `targetValueWeight`
- `minBehaviorProbability`
- `maxImportanceWeight`
- `bootstrapReplicates`
- `bootstrapSeed`
- `maxCandidateActions`
- `expectedDatasetSha256`
- `expectedBehavioralModelSha256`
- `expectedValueModelSha256`

Read status and artifacts:

```text
GET /deadlock/analysis/recommendation-policy-v4-evaluation/status
GET /deadlock/analysis/recommendation-policy-v4-evaluation/manifest
GET /deadlock/analysis/recommendation-policy-v4-evaluation/audit
GET /deadlock/analysis/recommendation-policy-v4-evaluation/evaluation
```

Only one evaluation can run at a time. Completing an evaluation does not change live recommendation serving.
